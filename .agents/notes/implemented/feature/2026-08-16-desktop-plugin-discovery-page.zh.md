# Agent Note: Desktop 插件发现页面

Status: implemented

[English](2026-08-16-desktop-plugin-discovery-page.md) | 中文

## Problem

插件中心同时承载目录浏览、已安装包管理、兼容性说明、恢复提示与生命周期动作。随着公开目录增长，用户需要更快地查看当前推荐和最近新增条目，同时不能继续增加管理页面的密度，也不能削弱其操作职责。

## Decision

Desktop 客户端在 `sidebar.primary.action` 中将 `plugin-discovery` 注册在 `plugin-center` 之后，并为其提供独立的 keyed `main.page`。插件发现通过同一个 Desktop 桥接消费现有公开插件目录和已安装投影；它不增加包来源、目录权限或变更路径。

概览保留目录由服务端拥有的精选、热门与最近更新顺序。页面展示一张精选卡片、紧凑热门排行、最近更新卡片、搜索，以及仅与返回的已审核元数据匹配的能力分类。客户端不计算热门分数，不把“最近更新”改写为保证当天发布，也不会在没有可审计目录字段时展示增长数字。

打开条目时保留发现位置，并展示右侧确定版本面板。面板读取现有详情和兼容性决定；安装继续使用现有兼容检查、对广泛权限的明确确认、只含不可变插件 id 和版本的意图，以及操作进度对话框。已安装条目会打开插件中心进行管理，而不会重复提供启用、停用、更新或卸载控制。

## Interaction ownership

插件发现拥有搜索文字、所选视图、能力分类、所选详情与面板局部焦点。Desktop 目录拥有成员和顺序，兼容桥接拥有安装资格，操作桥接拥有进度，插件中心仍是唯一的已安装组合管理器。

## Alternatives considered

**在插件中心增加另一个分区。** 这种方式只保留一个入口，但会让发现功能与已安装状态、恢复、配置和生命周期动作在已经密集的页面中竞争。

**展示客户端计算的增长和下载指标。** 当前摘要没有可审计的时间序列证据，因此推导或装饰性数字会错误表达目录事实。

**复制公开导航站的落地页。** 大型营销标题和分类宫格会低效占用桌面空间，并破坏现有 Harness 导航与卡片密度。

## Consequences

用户获得独立、紧凑的发现旅程，同时每次安装仍然经过受信任的 Desktop 路径。页面只能展示当前目录元数据支持的排行含义和分类；未来的增长视图必须先增加目录合同和后端证据，UI 才能加入。
