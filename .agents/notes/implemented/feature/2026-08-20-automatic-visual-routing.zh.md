# Agent Note: 单一开关下的自动视觉路由

Status: implemented

[English](2026-08-20-automatic-visual-routing.md) | 中文

## Problem

Desktop 已经提供兼容视觉旁路，而 Harness 又为具备能力的对话模型增加了原生图片输入。如果两套机制分别暴露，用户会面对含义重叠的控制项，同一张图片也可能同时进入主要模型与旁路。当前模型本身可以接收图片时仍要求配置兼容提供方 Key，也会增加没有必要的门槛。

## Decision

输入区只保留一个面向用户的 `视觉增强` 开关。从关闭状态启用时，系统会先为当前会话及后续空白会话选择内置 `DeepSeek-V4-Flash-Vision-Exp` 模型，再开启其原生图片路线。能力保持开启后，如果用户再次切换模型，系统仍根据确切模型元数据选择且只选择一条路径：元数据包含 `image` 时使用原生图片输入，否则使用已经验证的兼容旁路。没有声明图片能力且没有可用兼容提供方的模型进入 `unavailable`，系统打开既有提供方配置，而不是接收图片。

Host 通过 `vision.route` 与原子操作 `vision.activate` 持有路由决定。启用原生路径时只写入开启设置，不要求视觉提供方凭证；启用兼容路径时必须存在已经配置且完成验证的提供方。客户端读取当前 Session 经 Host 接受的模型选择；能力关闭时，点击按钮会先选择内置视觉模型，再启用路线，悬浮卡片则说明解析出的路线，而不会增加第二个模式选择器。能力开启期间切换模型会重新计算路线。DeepSeek 模型编辑器中的“允许原生图片请求”只是单个模型的能力声明，并不是路由控制，因此私有或后续新增的视觉模型也能为同一套自动决策提供明确元数据。

在 LLM 边界，原生路径只把包含原图的请求向下委托一次。兼容路径继续把图片块替换成现有的持久视觉观察，不再发送原图。开关关闭时，新图片 Prompt 会在附件持久化前被拒绝；历史图片块则被替换成明确的模型可见省略标记，界面与持久附件历史本身保持不变。

对于内置的 `DeepSeek-V4-Flash-Vision-Exp` 路线，Studio 直接复用 Harness rc.2 图片管线，不增加第二套 Desktop 传输。附件服务采用官方 20 MiB 单张源图片默认上限，并生成一份有界、确定的请求图片版本。DeepSeek 通常收到可复用的 Files API `file_id`；Files 解析失败或超时时，完整请求会把同一份已准备字节作为有界内联 Data URL 回退。单次请求不会混用文件 ID 与内联图片，两条原生分支也都不会调用兼容旁路。

本决策把确切模型的原生能力，与[可选择视觉提供方](2026-08-16-selectable-visual-providers.zh.md)中的云端及自托管旁路组合起来。它只在用户启用已关闭的快捷按钮时改变模型选择，不改变提供方凭证、附件存储或设置弹窗中的兼容提供方配置。

## Alternatives considered

**提供“自动、原生、Qwen 兼容、关闭”四种模式。** 不采用：原生和兼容是由模型能力决定的实现路径，不是彼此独立的用户目标。模式菜单会重复模型选择器与提供方设置，还会允许用户选择实际无法运行的组合。

**开启后始终运行兼容视觉旁路。** 不采用：具备原生能力的模型只能收到文字观察而非原图；如果随后再发送原图，还会造成重复处理、额外延迟和提供方费用。

**始终把图片发给当前对话模型。** 不采用：明确只支持文本的模型需要已经验证的兼容路径，否则 Prompt 接受后仍会失败。

**开关关闭时仍允许原生图片。** 不采用：唯一可见开关必须控制完整产品能力。如果界面显示关闭但原生图片仍进入模型，界面状态就是错误的。

## Consequences

用户只需启停一个能力，使用内置原生视觉模型时无需另配兼容提供方 Key。首次启用会让现有模型选择器明确显示模型变化；之后再次切换模型可能改变实际路线，Host 会在 Prompt 准入与流调用时重新检查。自动原生路由有意以明确证据为准：未声明模态的适配器会使用兼容路径，只有声明 `image` 后才会收到原始图片块。Files 复用减少重复上传工作，有界的全内联回退则让单次请求可恢复而不重复发送图片。关闭功能会阻止模型读取图片，但不会删除附件或重写 Session 历史。
